# SmartBin — умная мусорка с автоматической сортировкой

Многостраничный сайт-магазин умных урн SmartBin: каталог с фильтрами, карточки товаров,
корзина с оформлением заказа, чат поддержки и всплывающие уведомления.

Сайт статический: ни сборки, ни npm-зависимостей, ни бэкенда — достаточно любого
статического хостинга, включая GitHub Pages.

## Страницы

| Файл | Что внутри |
| --- | --- |
| `index.html` | Главная: hero, «Как это работает», популярные модели, преимущества, CTA |
| `catalog.html` | Каталог: фильтр по категориям, поиск, сортировка по цене |
| `product.html?id=…` | Карточка товара: описание, характеристики, количество, похожие товары |
| `cart.html` | Корзина: состав заказа, доставка, форма оформления, история заказов |
| `support.html` | Поддержка: чат с оператором, FAQ, контакты |
| `admin.html` | Админ-панель: заказы, товары, телеметрия урн (вход по паролю) |

## Возможности

- **Уведомления (тосты)** вместо `alert()`: четыре типа (успех, ошибка, предупреждение,
  информация), иконки, полоса таймера, закрытие крестиком, пауза при наведении,
  стек до четырёх штук, на мобильных — снизу экрана.
- **Корзина в `localStorage`** — сохраняется между страницами и после закрытия браузера:
  добавление в один клик, изменение количества, удаление, очистка, счётчик в шапке
  с анимацией.
- **Оформление заказа** — валидация имени, телефона, email, города и адреса, выбор
  доставки или самовывоза, расчёт доставки (бесплатно от 50 000 ₽), номер заказа
  и сохранение истории последних заказов.
- **Каталог** — фильтры по категориям, поиск по названию и описанию, сортировка по цене,
  пустое состояние с сбросом фильтров, фильтр из ссылки (`catalog.html?filter=part`).
- **Наличие** — товары без наличия показываются серыми, уходят в конец списка,
  кнопка «В корзину» у них заблокирована на карточке и на странице товара.
- **Карточка товара** — данные из общего каталога, счётчик количества, характеристики,
  блок похожих товаров, заглушка для неизвестного `id`.
- **Чат поддержки** — имитация оператора: индикатор набора, ответы по ключевым словам
  (доставка, гарантия, цены, оплата, подбор модели), быстрые вопросы из FAQ.
- **Адаптивность и доступность** — мобильное меню, корректные `aria`-атрибуты,
  `prefers-reduced-motion`, фокус-стили, семантические `details` для FAQ.

## Админ-панель

Открывается по адресу `admin.html`, демо-пароль — `smartbin`. Сессия хранится в `sessionStorage`,
данные — в `localStorage` браузера.

| Раздел | Что делает |
| --- | --- |
| Обзор | Заказы, выручка, средний чек, счётчик урн к вывозу, последние заказы и самые заполненные отсеки |
| Заказы | Таблица заказов с клиентами и статусами («Новый / В работе / Выполнен»), демо-данные и очистка |
| Товары | Правка цены и наличия — изменения сразу видны в каталоге, карточке товара и корзине |
| Урны | Заполнение четырёх отсеков по каждой урне, цветовые пороги 60% и 80%, симуляция вбросов |

Прямые ссылки на разделы: `admin.html?view=orders`, `?view=products`, `?view=bins`.

## Общие данные между устройствами

По умолчанию панель пишет в `localStorage` — это значит, что правки видны только в одном браузере.
Чтобы данные менялись на всех устройствах, они хранятся в файле репозитория `data/store.json`:

- **Чтение** — открытое: витрина при загрузке тянет файл через GitHub API (свежие данные),
  запасной путь — `raw.githubusercontent.com` на случай лимита запросов. Токен не нужен.
- **Запись** — через GitHub API: панель коммитит файл по кнопке или автоматически через 0,9 с после правки.
  Нужен fine-grained токен с правом **Contents: Read and write** на этот репозиторий.

Как включить запись:

1. GitHub → Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate new.
2. Repository access: *Only select repositories* → `SmartBin`.
3. Permissions → Repository permissions → **Contents: Read and write**. Срок — 30 дней.
4. Открыть `admin.html` → раздел **Синхронизация** → вставить токен → включить переключатель → «Сохранить».
5. Нажать «Отправить сейчас» — файл появится в репозитории.

После этого телефон, планшет и второй компьютер видят те же цены и заказы: витрина читает файл
при каждой загрузке, кэш обновляется раз в 20 секунд.

> Токен хранится только в `localStorage` того браузера, где вы его ввели, и никогда не попадает в репозиторий.
> Файл `data/store.json` публичный — не вводите в заказы реальные телефоны и адреса.
> Отозвать доступ можно в любой момент в настройках GitHub.

> **Важно:** это статический сайт без серверной части. Пароль скрывает интерфейс, а не данные:
> любой, кто откроет исходники, увидит логику. Для реальных заказов нужен бэкенд с настоящей
> аутентификацией и базой данных — текущая панель годится только для демонстрации сценария.

## Чат поддержки

Сообщения с сайта приходят в админку (раздел **«Обращения»**), а ответ оператора появляется в чате
у посетителя. Работает на статическом хостинге: приёмником служит бесплатное веб-приложение Google Apps Script.

Включение (5–10 минут):

1. Открыть https://script.google.com → **Новый проект**.
2. Вставить код из [`docs/apps-script-chat.gs`](docs/apps-script-chat.gs).
3. **Развернуть** → *Новое развёртывание* → тип **Веб-приложение**, запуск от имени себя, доступ — **Все**.
4. Скопировать адрес, заканчивающийся на `/exec`.
5. В файле `data/chat.json` записать: `{ "inbox": "https://script.google.com/macros/s/.../exec" }`.
6. Перезагрузить админку — раздел «Обращения» начнёт получать сообщения.

Пока `inbox` пустой, чат на сайте работает в демо-режиме: отвечает заготовками и никуда не пишет.

Протокол приёмника: `GET ?action=list` — список сообщений, `POST {action:'send'|'reply'}` — новое сообщение или ответ.
Хранилище — Google Таблица «SmartBin chat» на вашем Диске.

> Адрес веб-приложения публичный: теоретически кто угодно может отправить туда сообщение.
> Для демо это допустимо; для продакшена нужен бэкенд с авторизацией и антиспамом.
> Ответ виден посетителю, только пока открыта страница поддержки (опрос раз в 8 секунд).

## Заказы с сайта

Оформленный заказ уходит в тот же канал, что и чат, и появляется в админке в разделе **«Заказы с сайта»**:

- состав заказа, сумма, клиент, телефон, адрес и способ получения;
- статусы «Новый / В работе / Выполнен», которые сохраняются на сервере;
- счётчик новых заказов в меню.

Если развёрнут старый скрипт без таблицы заказов, сайт отправляет заказ обычным сообщением,
а панель показывает его с пометкой «из чата» — данные не теряются, но статусы недоступны.
Чтобы включить таблицу заказов, замените код на новый из [`docs/apps-script-chat.gs`](docs/apps-script-chat.gs)
и разверните новую версию (адрес `/exec` не меняется).

Заказы и сообщения хранятся в Google Таблице на вашем Диске — в отличие от публичного
репозитория, персональные данные посетителей там не видны посторонним.

## Запуск

Откройте `index.html` в браузере — этого достаточно для просмотра.
Для корректной работы переходов между страницами и `localStorage` удобнее локальный сервер:

```bash
python -m http.server 8000
# затем http://localhost:8000
```

## Публикация на GitHub Pages

1. Settings → Pages.
2. Source: *Deploy from a branch*, ветка `main`, папка `/ (root)`.
3. Сайт откроется по адресу `https://<username>.github.io/<repo>/`.

## Технические детали

- HTML5, CSS3 (переменные, grid, flexbox), чистый JavaScript (ES6), без фреймворков.
- Данные товаров — массив `PRODUCTS` в `assets/js/app.js`; цены форматируются через `Intl.NumberFormat`.
- Ключи хранилища: `smartbin_cart_v1` (корзина), `smartbin_orders_v1` (последние 10 заказов).
- Общие компоненты (шапка, подвал, тосты) подключаются на каждой странице через `style.css` и `app.js`.

## Ограничения демо

- Оплата не подключена: заказ сохраняется только в браузере и никуда не отправляется.
- Ответы поддержки имитируются на клиенте, реального оператора нет.
- Админ-панель работает на `localStorage`: данные видны только в том браузере, где их создали.
- Общая синхронизация идёт через файл репозитория — это нужно один раз настроить токеном.
- Товары, цены, урны и контакты вымышлены.
